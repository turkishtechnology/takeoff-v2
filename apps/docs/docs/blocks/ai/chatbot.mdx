# Chatbot

A chat assistant panel with a header, a scrolling conversation and a message
composer. It is a **block**: there is no `Chatbot` export in
`@takeoff-ui/react-spar`. Copy [`Chatbot.tsx`](#source) into your app and
connect it to your own backend or AI SDK.

The block is built from `Card`, `Badge`, `Button`, `Chip`, `Dropdown`, `Input`
and `Skeleton`, and imports its icons from `@takeoff-icons/react`. Add that
package to your app if it is not already a direct dependency:

```bash
pnpm add @takeoff-icons/react
```

Requirements:

- `@takeoff-ui/react-spar` 0.6.0 or later and `@takeoff-icons/react` 0.4.0 or
  later.
- Tailwind CSS v4 with `@takeoff-design/tailwind`. The block uses v4-only
  variants such as `starting:` and `in-data-[theme=dark]:`. Make sure Tailwind
  scans the folder you copy `Chatbot.tsx` into.

## Quick start

1. Copy [`Chatbot.tsx`](#source) into your app, for example to
   `src/components/Chatbot.tsx`. It is the only file you need; the file is yours
   to change.
2. Render `ChatbotLauncher` for the floating button, or `Chatbot` to place the
   panel in a page.
3. Keep the conversation in your own state and answer from your backend or AI
   SDK in `onSubmit`:

```tsx
import { useState } from 'react';
import { ChatbotLauncher, type ChatbotMessage } from './components/Chatbot';

export function SupportChat() {
  const [messages, setMessages] = useState<ChatbotMessage[]>([
    {
      id: 'welcome',
      role: 'assistant',
      content: 'Hi, how can I help with your trip?',
    },
  ]);
  const [typing, setTyping] = useState(false);

  const send = async (text: string) => {
    const id = crypto.randomUUID();
    setMessages(current => [
      ...current,
      { id, role: 'user', content: text, status: 'sent' },
    ]);
    setTyping(true);
    try {
      const answer = await askMyAssistant(text); // your API or AI SDK
      setMessages(current => [
        ...current,
        { id: crypto.randomUUID(), role: 'assistant', content: answer },
      ]);
    } catch {
      // Mark the message as not sent; pass onRetry to offer Retry.
      setMessages(current =>
        current.map(message =>
          message.id === id ? { ...message, status: 'failed' } : message,
        ),
      );
    } finally {
      setTyping(false);
    }
  };

  return (
    <ChatbotLauncher messages={messages} typing={typing} onSubmit={send} />
  );
}
```

Everything else is opt-in through props, and each example below shows one of
them with its code. The examples share [`useDemoConversation`](#source), a
demo-only hook that answers with a canned reply in place of a backend. Do not
copy it; use your own state and service as above.

## Floating

`ChatbotLauncher` renders the floating button (Figma `chatbot-fab`) that opens
the panel above it with a short scale-and-fade animation. The button darkens and
lifts on hover and presses in when clicked. Escape or the close button closes
the panel and returns focus to the launcher; the draft is kept.

Use `assistantBubble` and `userBubble` to style the two sides separately, as in
the Figma widget, and `userAvatar` for the user's picture. `menuItems` fills the
more (⋮) menu in the header; this example offers a new chat, a download of the
conversation and mute.

## Message status and undo

A user message shows a clock while `status` is `sending`, one tick when `sent`
and a double tick when `read`. While a message is `undoable` and `onUndo` is
set, Undo appears under it; your code clears `undoable` when the undo window
ends. A message with `retracted` is replaced by a note. This example offers Undo
for up to 5 seconds, until the bot reads the message; send a message to try it.

## Attachments and rich messages

The plus button opens a menu where the user picks what to attach: a photo or
video, a document, or any file. The choice sets what the file picker accepts.
Picked files appear above the composer, where each one can be removed, and are
passed to `onSubmit(text, files)`. A message can carry `attachments`, which
render as thumbnails for images and as file links otherwise. Change the choices
with `attachmentOptions` (a single option skips the menu), or hide the button
with `allowAttachments={false}`.

Anything in a message's `extra` renders inside its bubble, under the text. This
example uses it for suggestion chips, a flight card with an image, and Yes / No
buttons, as in the Figma structured response.

## Connecting your data

The block keeps only the draft text and the picked files. Your code owns the
conversation:

- Pass the conversation as `messages`. Each message has an `id`, a `role`
  (`assistant`, `user` or `system`), `content`, and optionally `attachments`,
  `extra`, `time`, `day`, `status`, `retracted`, `undoable`, `feedback`,
  `author`, `streaming`, `sources` and `suggestions`.
- `onSubmit(text, files)` fires when the user sends. Upload the files, append
  the user message, set `typing` while you wait, then append the answer.
- To stream a reply, append an empty assistant message with `streaming: true`
  and update its `content` as chunks arrive. Set `streaming` back to `false`
  when the stream ends or fails; until then the answer actions stay hidden. The
  log announces added messages, not text that changes inside one, so screen
  readers do not hear streamed text. If that matters for your product, append
  the finished reply as its own message, or announce it in a visually hidden
  `role="status"` element when the stream ends.

`content` is a `ReactNode`, so you can render markdown with the renderer your
app already uses.

## Accessibility

- The conversation is a `role="log"` region, so screen readers announce new
  messages without moving focus. Sending keeps focus in the composer.
- New messages scroll into view only while the reader is at the bottom;
  scrolling up to re-read is never interrupted.
- Enter sends and Shift+Enter adds a line. Enter does not send, and Escape does
  not close, while an IME composition is open.
- The typing indicator is added to the log with a text label, so it is announced
  once. Its animation, the message fade-in and the panel animation stop under
  `prefers-reduced-motion`.
- Icon-only buttons carry an `aria-label`, each picked file has a labelled
  remove button, and the launcher exposes `aria-expanded`. The closed panel is
  `inert`.
- Delivery states have a visually hidden label, the unread count is part of the
  launcher's label, the thumbs are toggle buttons (`aria-pressed`), and copying
  is announced.
- While offline or disabled, the message field is read-only and `aria-disabled`,
  so it keeps focus, and it is described by the notice, and near `maxLength` by
  the character count.
- Suggestions are a labelled group of buttons. Pressing one keeps focus in the
  composer, and accepting consent moves focus there.
- The jump button and the dividers are visible cues only: the log already
  announces new messages. Day and new-message dividers are `role="separator"`
  with a label.
- The microphone is a toggle button (`aria-pressed`), the stars of
  `ChatbotRating` are labelled toggle buttons in a labelled group, and the
  thanks is announced.
- While loading, the log is `aria-busy` and the skeleton has a status label.
  Loaded history, the first page and older pages, is added while the log is
  muted for a moment, so screen readers do not read it out as new messages.
- The composer grows with its content through `field-sizing: content`; browsers
  without it (Firefox, older Safari) keep a single row that scrolls.

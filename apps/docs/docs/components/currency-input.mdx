`CurrencyInput` is an amount field paired with a currency selector. It renders
the styled [`Input`](./input) for its chrome — border, sizing, focus ring,
disabled/invalid state, clear button — and layers the amount and currency state
on top, so everything you know about `Input` still applies.

Formatting is done entirely with the platform's `Intl.NumberFormat`. There is no
locale table and no formatting dependency: separators, fraction digits, and
symbol placement all come from the runtime, which is why `tr-TR` renders
`1.234,56 ₺` correctly out of the box.

## Usage

```tsx
import { CurrencyInput, Field } from '@takeoff-ui/react-spar';
```

```tsx
<Field>
  <Field.Label />
  <CurrencyInput>
    <CurrencyInput.Prefix />
    <CurrencyInput.Field />
    <CurrencyInput.ClearButton />
    <CurrencyInput.Suffix>
      <CurrencyInput.CurrencySelect />
    </CurrencyInput.Suffix>
  </CurrencyInput>
  <Field.Description />
  <Field.ErrorMessage />
</Field>
```

The anatomy is explicit: the root renders no field of its own, exactly like
`Input`. `CurrencyInput.Prefix`, `Suffix`, `ClearButton`, and `Spinner` are the
same components `Input` exposes, re-published here so a currency input is
composed from a single namespace.

## The value is a number

The committed value is a plain `number` — never the formatted string. An empty
field commits `undefined` rather than `0`, so "no amount entered" stays
distinguishable from a real zero.

## Formatting happens on blur

While the field has focus you edit a plain, ungrouped string (`1234,56`); on
blur it settles into the full display form (`1.234,56 ₺`). Reformatting on every
keystroke is what makes masked inputs jump the caret, so it is deliberately not
done here. Pasting a fully formatted value still parses — stray symbols,
grouping separators, and non-breaking spaces are all tolerated.

## Symbol placement

Where the selector goes is a composition decision, not a prop: put it in
`Suffix` for the Turkish trailing-symbol convention, or in `Prefix` for the

## Locales and currencies

`locale` drives grouping, decimals, and symbol placement; `currency` (ISO 4217)
drives the symbol and the natural fraction digits. Pass `locale` explicitly —
leaving it to the runtime lets the server and the browser disagree and produces
a hydration mismatch.

## Customizing the picker

`CurrencyInput.CurrencySelect` takes render props for both the trigger and the
panel items, so symbol/name/code ordering and localized names need no new part.

If you outgrow it entirely, `useCurrencyInputContext()` exposes the amount and
currency state so you can build a bespoke picker and bind it to the same input:

```tsx
import { useCurrencyInputContext } from '@takeoff-ui/react-spar';

function MyCurrencyPicker() {
  const { currency, setCurrency } = useCurrencyInputContext('MyCurrencyPicker');
  // …render anything, then call setCurrency(code)
}
```

Because the selector reads from context rather than from its position in the
DOM, it behaves identically wherever you place it.

## Accessibility

- The selector trigger collapses to a bare symbol, so it carries an explicit
  accessible name. Override it with `aria-label` when the default
  (`"Para birimi"`) does not fit your product's language.
- Each panel item sets `label`, which is both the trigger's text representation
  and the typeahead search key — start typing a currency name to jump to it.
- The amount field uses `inputMode="decimal"` so touch keyboards open on digits,
  and disables autocomplete.
